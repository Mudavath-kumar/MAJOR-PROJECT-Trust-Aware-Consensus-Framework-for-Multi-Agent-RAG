## 📌 Executive Summary

TrustRAG retrieves tenant-scoped document chunks, asks a researcher to propose claims, checks those claims against retrieved evidence, and has a critic flag unsupported claims. A deterministic decision engine then chooses answer, partial answer, or abstention. The trust assessor is a retrieval-signal calculation, not a separate language-model agent.

Every answer generated by TrustRAG carries:
1. **Decision score**: A weighted operational heuristic over retrieval similarity, verified-claim coverage, citation coverage, and critic risk. It is not a calibrated probability.
2. **Verifier–critic agreement**: Agreement between claim-support verdicts; not a vote among five independent agents.
3. **Online audit signals**: Claim-support and retrieval-similarity proxies. Answer relevance is not scored online, and none of these is a substitute for a labeled evaluation set.
4. **Evidence trace**: Retrieved/cited chunk IDs and source metadata. PDF page-level and token-offset citations are not currently produced.

## ✨ Key Features

### 🤖 Evidence verification and decision pipeline
- **Researcher (LLM)** — Proposes answer claims from the retrieved chunks.
- **Fact Checker (LLM)** — Assigns typed support verdicts and may use configured external search for additional context. External search results are not promoted to user-document evidence.
- **Critic (LLM)** — Flags unsupported claims or elevated risk.
- **Trust signal (deterministic)** — Summarizes retrieval similarity; it does not independently establish factual trust.
- **Consensus engine (deterministic)** — Applies the configured threshold and returns only claims that have verifier support, retrieved evidence IDs, and no critic unsupported-claim flag.

### 📊 Runtime audit signals
- **Verified claim support**: Fraction of proposed claims accepted by the verifier, with critic flags removed; an online heuristic, not human-labeled faithfulness.
- **Retrieval similarity**: Mean/vector similarity signal, not gold-labeled context precision.
- **Answer relevance**: Not measured by the online pipeline.
- **Critic risk estimate**: A model-generated risk category, not a measured hallucination rate.
- **Verifier–critic agreement**: Claim-level verdict agreement; not an independent-agent quorum.

### 📁 Multi-File Document Ingestion
- Upload and parse up to 10 files per batch, up to 25 MB each: **PDF, DOCX, TXT, Markdown, CSV, and JSON**.
- Intelligent document chunking with metadata tagging, sentence boundary preservation, and token length controls.
- Automatic vectorization via the configured Gemini embedding service (`gemini-embedding-2`) stored in MongoDB Atlas Vector Search.

### 🛡️ Enterprise Security & Data Isolation
- **Tenant Isolation**: Every document and vector chunk is strictly partitioned by `user_id` and selected document IDs are checked by the backend before retrieval.
- **Clerk Authentication**: Seamless Email/Password and Google OAuth with automatic session token verification.
- **Audit Logs & Compliance**: Export query histories and evaluation matrices as compliance-ready JSON or CSV reports.
- **Content Security**: File type validation, size quotas, sanitize pipelines, and granular error masking.

## 🚀 Quick Start

### Prerequisites
- **Node.js 20+** and **pnpm** (npm also works for the backend)
- **Python 3.11+** with `pip`
- **MongoDB** (Local instance or free [MongoDB Atlas](https://www.mongodb.com/atlas) cluster)
- **Clerk Account** (Free tier at [clerk.com](https://clerk.com))
- AI Provider API Key: **Google Gemini** or **OpenRouter**

### 1. Repository Setup
```bash
git clone https://github.com/Mudavath-kumar/MAJOR-PROJECT-Trust-Aware-Consensus-Framework-for-Multi-Agent-RAG.git trustrag
cd trustrag
```

### 2. Environment Configuration

Create the respective `.env` files for each tier:

#### **Frontend (`.env.local` in project root)**
```env
VITE_API_URL=http://localhost:3001/api/v1
VITE_CLERK_PUBLISHABLE_KEY=pk_test_your_clerk_publishable_key
```

#### **Backend (`backend/.env`)**
```env
NODE_ENV=development
PORT=3001
MONGODB_URI=mongodb://localhost:27017/trustrag
JWT_SECRET=your-secure-jwt-secret-string
CLERK_SECRET_KEY=sk_test_your_clerk_secret_key
CLERK_PUBLISHABLE_KEY=pk_test_your_clerk_publishable_key
AI_SERVICE_URL=http://localhost:8000
FRONTEND_URL=http://localhost:5174
AI_SERVICE_TOKEN=the_same_long_random_value_as_ai_service
SETTINGS_ENCRYPTION_KEY=another_long_random_value
B2_ENDPOINT=https://s3.us-east-005.backblazeb2.com
B2_REGION=us-east-005
B2_KEY_ID=your_backblaze_key_id
B2_APPLICATION_KEY=your_backblaze_application_key
B2_BUCKET_NAME=trustrag-documents-00
```

#### **AI Service (`ai-service/.env`)**
```env
GEMINI_API_KEY=your_gemini_api_key
OPENROUTER_API_KEY=your_openrouter_api_key
GEMINI_MODEL=gemini-3.8-flash
EMBEDDING_MODEL_NAME=gemini-embedding-2
MONGODB_URI=mongodb://localhost:27017/trustrag
AI_SERVICE_TOKEN=the_same_long_random_value_as_backend
TAVILY_API_KEY=optional_tavily_key
EXTERNAL_VERIFICATION_ENABLED=true
```

---

### 3. Launch Services Locally

You can run all three services concurrently in separate terminal tabs:

#### **Terminal 1: AI Service (FastAPI)**
```bash
cd ai-service
python -m venv venv
# Windows:
venv\Scripts\activate
# Linux/macOS:
source venv/bin/activate

pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

#### **Terminal 2: Backend API (Express)**
```bash
cd backend
npm install
npm run dev
```

#### **Terminal 3: Frontend (TanStack Start)**
```bash
# In project root:
pnpm install
pnpm run dev
```

Open [http://localhost:5174](http://localhost:5174) to access the TrustRAG workspace.

## ☁️ One-Click Render Deployment

The repository includes a `render.yaml` blueprint defining the backend and AI services with automated health checks and private service linking. Deploy the frontend separately on Vercel:

1. Fork or push this repository to GitHub.
2. Sign in to [Render Dashboard](https://dashboard.render.com).
3. Click **New +** ➡️ **Blueprint**.
4. Connect this repository — Render will automatically read `render.yaml` and provision:
   - `trustrag-backend-j3oe` (Node.js API Service)
   - `trustrag-ai-service` (FastAPI Python Service with Dockerfile)
5. Fill in `MONGODB_URI`, `GEMINI_API_KEY` and/or `OPENROUTER_API_KEY`, `TAVILY_API_KEY` if external verification is enabled, the same `AI_SERVICE_TOKEN` in both services, Backblaze B2 credentials, Clerk credentials, `SETTINGS_ENCRYPTION_KEY`, and the Vercel URL in `CORS_ALLOWED_ORIGINS`.
6. Deploy!
